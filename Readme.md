# Terraform and Ansible

A repository that automates provisioning and configuring cloud infrastructure on AWS using Terraform and Ansible.

## Overview

The project follows a three-phase Infrastructure-as-Code workflow:

1. **Provision** — Terraform creates AWS resources (EC2 instances, security group, SSH key pair)
2. **Bootstrap** — Ansible connects as the default `ubuntu` user and sets up a dedicated `ansible-user` service account
3. **Configure** — Ansible reconnects as `ansible-user` and installs software on each server group via roles

## Infrastructure

- **3x Ubuntu 22.04 LTS** EC2 instances (`t2.micro`) in `ca-central-1`, split into:
  - **2 web servers** (`Ubuntu-1`, `Ubuntu-2`)
  - **1 DB server** (`Ubuntu-3`)
- **Security group** with inbound rules restricted to a single trusted IP:
  - SSH (22), RDP (3389), HTTP (80)
  - All outbound traffic allowed
- **RSA 4096-bit key pair** generated by Terraform and used for initial SSH access

## Project Structure

```
provisioning/
  main.tf              # Terraform config — EC2, security group, key pair
  deploy-infra.ps1     # Runs Terraform, generates grouped Ansible inventory, copies keys
  destroy-infra.ps1    # Cleans up local files and destroys AWS resources

configuring/
  ansible.cfg          # Ansible defaults for post-bootstrap (ansible-user, ~/.ssh/ansible)
  bootstrap.yml        # Playbook — OS update and ansible-user setup (run first)
  configure-servers.yml  # Playbook — applies roles to web_servers and db_server groups
  files/
    sudoers-ansible-user  # Grants ansible-user passwordless sudo
  roles/
    web_servers/tasks/main.yml  # Installs Apache + PHP, ensures service is running
    db_server/tasks/main.yml    # Installs MariaDB, ensures service is running

ansible.cfg            # Ansible defaults for bootstrap phase (ubuntu user, RSA key)
```

## Workflow

### Deploy
```powershell
cd provisioning
.\deploy-infra.ps1
```
This runs `terraform apply`, extracts the instance public IPs, writes them to `configuring/inventory`, and copies the SSH keys to the `configuring/` directory.

### Bootstrap
```bash
ansible-playbook configuring/bootstrap.yml
```
Run from the project root (uses root `ansible.cfg` — connects as `ubuntu` with the Terraform RSA key). Runs on all instances and:
- Runs a full OS dist-upgrade
- Creates an `ansible-user` account (group: root, shell: bash)
- Installs an ed25519 SSH public key for `ansible-user`
- Drops a sudoers file granting `ansible-user` passwordless sudo

### Configure
```bash
cd configuring
ansible-playbook configure-servers.yml
```
Run from `configuring/` (uses its own `ansible.cfg` — connects as `ansible-user` with `~/.ssh/ansible`). Applies roles to each host group:
- **web_servers** (`Ubuntu-1`, `Ubuntu-2`) — installs Apache + PHP, starts `apache2`
- **db_server** (`Ubuntu-3`) — installs MariaDB, starts `mariadb`

### Destroy
```powershell
cd provisioning
.\destroy-infra.ps1
```
Removes the generated inventory and key files, then runs `terraform destroy`.
